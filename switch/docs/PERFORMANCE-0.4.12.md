# 0.4.12 每帧开销优化测试版

用户反馈走动、转动镜头时持续低帧率。本版保留默认 1280×720，先减少渲染桥的 CPU 工作；未通过降低清晰度、超频或改变游戏速度制造帧率提升。

- 图形函数入口在每个 GuestGl/上下文内查找一次并缓存。销毁上下文后缓存一起释放；缺失函数仍报错。
- 顶点/法线/颜色/纹理坐标及索引暂存区复用已分配容量，避免每次绘制创建、清零和释放新的同尺寸容器。每次依然校验范围并读取最新游戏内存，不缓存旧的几何内容。
- 保留 0.4.11 的独立 VBO/EBO 每次替换存储路径，防止优化绕开之前的兼容处理；保留原版材质、灯光设置和按键。
- Switch 每 120 次显示记录一次实际时间窗口：mean_ms、max_ms 和 present_mean_ms。前两项为相邻显示完成之间的平均/最大间隔；最后一项含菜单光标绘制与交换等待。它们可帮助区分瓶颈，但不是独立的 GPU 执行计时；窗口可能包含加载或暂停。

## 已完成验证

Windows 原生 GLES1/Mesa llvmpipe 像素回归通过：旧客端与独立缓冲路径、索引内容在同地址改变后的画面更新、VBO/EBO 绑定恢复、灯光及透明等既有检查。测试验证同一桥实例内每个请求的图形函数只解析一次。连续 1,220 帧进入用户存档对应房间，无运行时错误，输出截图中未见此前的密集黑白噪点。

主机有固定等待、软件渲染和不同 CPU，不能把主机耗时换算为 Switch 帧率，也没有量化承诺实机性能增幅。实机持续走动/转动镜头、战斗、重复启动、后续电梯及头盔/背部噪点仍待验证。新日志可定位下一轮瓶颈。原先设备噪点的根因仍未证实。

覆盖安装同一应用 ID，不删除 deadspacemobile 或存档。若性能仍低，提供新版 startup-latest.log，注明测试场景。公开同步仅含自制源码和说明；游戏资源、保存文件、密钥及整合 NSP 保留本地。
