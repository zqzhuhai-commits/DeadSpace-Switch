# 0.4.2：先检查基础启动，再测试游戏

已知反馈：用户的 23.0.1 系统、大气层环境可运行旧版；0.4.0、0.4.1 点击后退出，0.4.1 没有生成启动日志。大气层具体版本尚未提供。没有日志不能单独证明是系统加载拒绝，也可能是服务初始化或 SD 写入失败。

## 第一步：小测试包（约 260 KB）

安装并启动 **DeadSpace-BootCheck-0.4.2.nsp**。主菜单名称是 **Dead Space Boot Check**，使用默认自制程序图标。

正常时应显示 `BOOT CHECK PASSED`，并显示系统编码和 SD 日志是否可写；按 + 退出。它不启动游戏，不需要游戏资源，不加载 SDL、音频、ARM32 运行时或 Dynarmic。使用独立 Title ID `0100D5ACE0041000`，不会替换游戏包。

日志位置：`/switch/deadspacemobile/bootcheck-latest.log`。

请先反馈这个包是显示成功画面，还是同样立即退出。若它也退出且没有日志，后续应重点排查 NSO/基础服务/系统加载，而不能继续按游戏资源加载问题处理。

## 第二步：仅在第一步成功后测试兼容游戏包

安装 **DeadSpace-Mobile-ZH-0.4.2-Compat.nsp**，约 266 MB。程序与游戏资源全部内置，保留重制运行时及 0.4.1 启动日志；已有 SD 存档不覆盖。Title ID 仍为 `0100D5ACE0040000`。

这版恢复旧版分支的应用权限策略：16 MB 系统资源预留、优化内存分配、文件系统权限 `0x200001`、明确的服务列表、旧版线程优先级范围和句柄上限。额外保留当前链接代码实际包含的 UnmapTransferMemory 调用。两个包都使用该策略。

该策略来自旧版运行分支 `f1804752039b38d6db0a42516603e5649e544851` 的 `switch/package/npdm.json`，仅保留本项目的新 Title ID 并补全实际链接调用。旧配置与新配置的差异是排查线索，尚未被实机证明为闪退根因。

游戏日志位置：`/switch/deadspacemobile/startup-latest.log`。首条应含 `0.4.2-compat`。测试后把新日志复制到电脑，并提供完整路径。
