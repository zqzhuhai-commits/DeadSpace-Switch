# 0.4.7：加载限额、L 跑步与本地高清测试

## 已确认的问题与处理

用户 0.4.6 的失败启动日志在 NativeOnDrawFrame[1] 报 instruction budget exhausted。退出时资源读取仍有进展，累计 140420322 字节。该记录确认固定指令预算中断了加载，并不能证明自动保存文件损坏。

新的执行策略保留 2 亿条初始预算。每次预算耗尽，只有本次调用观察到新的资源读取才追加 1 亿条，总计最多 10 亿条；无读取进展不追加，仍保留 120 秒调用超时。规则覆盖所有绘制/加载调用及资源挂载，不局限于前五帧，因此后续关卡和检查点恢复同样适用。它不是无限取消卡死保护，也不能保证所有关卡绝无其他错误。

普通系统调用不再强制切换线程；保留剩余执行时间片，阻塞、主动让出或时间片耗尽时才调度。首次启动、后续资源加载和音频等待均使用同一规则。协作线程和实际 ARM32 阻塞/唤醒测试通过。

用户提供的四个 SBIN 保存文件，其分段边界和 FNV-1 校验码均通过。原压缩包保持不变，测试只使用副本；结构正确不等于所有保存状态语义均已验证。测试记录中，使用该副本确实触发了 LOAD BUDGET total=300000000 并继续进入菜单，没有要求删除保存目录。

## 按键

本版只按用户最后确认调整跑步：L 按住时随左摇杆发送原游戏跑步标志；ZL 瞄准。左摇杆仍为连续方向与幅度，右摇杆仍保持 0.4.6 降速后的镜头速度。R3 寻路、L3 陀螺开关、方向键下零重力跳跃均保持 0.4.6 配置。

跑步使用原生玩家 Vector2Event pad 1 的 flag 位，由原游戏状态处理器决定是否允许奔跑；不是把角色位置强行改快。手柄回归覆盖 L 的按住/松开和不干扰 ZL 瞄准。实际设备手感与特殊场景仍待验收。

## 本地高清实验

按用户要求，从 [DeadSpaceReanimated v1.3](https://github.com/GINESTR0/DeadSpaceReanimated/releases/tag/v1.3) 的 APK 提取纹理，未执行 APK，也未替换其 Android 运行时或原游戏库。下载全包大小 715366829 字节，SHA256 为 dbd94ee54fc3fefdddb101fac4eba1e2058a5db7cfcf30ac41ad96e88b285a3a，与发布记录一致。

提取 222 个 KTX，340222792 字节；与用户当前 donor 的 264 个 M3G 逐图精确哈希匹配，54 个键一致。保留最高 2048 尺寸的已有 mip 层；一张原图已是 2048、裁剪后没有提升，故回退原图。最终内置 53 张，64439932 字节。未匹配纹理保留原图，不能声称全游戏或中文字体全部高清。

正式启动入口已接入可选高清替换，显存预算 192 MiB；缺失、损坏、不兼容或超预算时回退原图。需要关闭时，在 /switch/deadspacemobile/hd.cfg 写入单个数字 0 后重启；没有该文件时默认开启。纹理参数只在原纹理参数改变后同步到替代对象，减少逐次绘制时的重复查询。

提取、精确匹配、已有 mip 层裁剪和边界拒绝测试通过。电脑真实游戏库 3900 帧回归实际替换 12 个当前场景纹理对象、上传 122 个 mip 层，未记录拒绝或预算跳过；这不代表 53 张已全部经过场景验证。独立进程复用基线保存目录，800 帧回归通过。

高清资源和含游戏内容的 NSP 仅保留用户本地，不上传公开仓库。该项目目前未公开运行时源码或明确资源复用许可；公开提交只包含本项目实现、提取/筛选工具和说明，不把公开下载误作再分发授权。

## 加载条与 60 秒目标

状态条移至屏幕顶部，避免遮住档案确认和“点击以继续”。显示已读 MB、返回帧数及经过时间；进入原生玩家 HUD 后收起。新增实际收起时间日志 elapsed_ms。

60 秒是优化目标，不是已实现的实机保证。不会到时伪造完成、强制隐藏仍在加载的状态，或退出游戏冒充完成。电脑参考测试的第 2 帧约 11 秒返回，新游戏 HUD 在第 720 帧、约 43 秒前具备收起条件；该时间不是 Switch 或模拟器成绩。

## 待验证与交付范围

最新 NSP 的独立解密回读、ExeFS/Control 对照、CNMT/内容哈希及 1802 个嵌入文件校验以交付报告为准。切关预算规则已实施，但完整剧情、电梯场景再次通过、设备上的重复启动、60 秒加载目标与高清性能仍需目标 Switch 验证。

电脑参考菜单背景可见异常多边形，关闭高清也存在；未据此声称 Switch 一定出现或已修复。本版是上机测试候选，不能当作完整流程验收成品。使用用户电梯后检查点副本，1500 帧恢复测试通过：从档案选择继续，进入实际玩家 HUD，末帧为无操作后的游戏内死亡提示，进程正常返回；该场景记录 18 个高清替换、189 个 mip 上传，无拒绝或预算跳过。这确认恢复路径能继续执行，不代表电梯后战斗和完整流程验收。一次并行测试曾因电脑内存不足出现 bad_alloc；释放重复中间文件并串行测试后通过，不能把该次失败当作已通过。
