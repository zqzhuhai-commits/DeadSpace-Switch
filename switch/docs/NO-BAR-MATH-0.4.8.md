# 0.4.8：电梯 modf 兼容修正，取消自制进度条

## 日志确认的问题

用户电梯处退出的记录明确为 `Unsupported import: modf`，原游戏调用方位于库偏移约 0x245be4，输入寄存器 r0=0x60000000、r1=0x40300a30、r2=输出指针。对应双精度输入为 16.0398006439209。此故障与此前资源加载预算不足不同，不应据此重置或判定自动保存文件损坏。

补齐原游戏实际导入的 modf 和 ldexp：按 ARM32 soft-float ABI 从 r0:r1 读取 double，modf 从 r2 取得整数部分输出地址并写回 8 字节，小数部分由 r0:r1 返回；ldexp 从 r2 读取有符号指数，结果由 r0:r1 返回。使用标准数学运算，保留符号、负零、NaN、无穷及范围错误处理，不返回假成功或固定零值。

## 回归与范围

新增回归覆盖原始日志参数、正负数、整值、正负零、NaN、无穷、输出指针越界和 ldexp 指数/极值。电脑测试还通过实际 Dynarmic ARM32 进口跳板调用 modf/ldexp，验证原日志输入得到整数 16 和正确的小数部分，确认寄存器返回与内存写回；测试入口仅在非 Switch 构建中、设置 DS_VERIFY_MATH 时启用。

最新用户存档四个文件的分段校验均通过。只在副本上运行恢复测试；原压缩包未改，程序不删除或重置用户进度。最新存档副本另完成 1500 帧恢复回归，进入玩家 HUD，未记录运行异常。完整电梯重新通过及后续关卡仍需设备验收，不能把数学函数回归等同于完整剧情测试。

## 取消进度条与版本标记

移除 Switch 游戏入口的自制加载覆盖层及其加载期间额外换帧，不再显示活动条、读取量、帧数或等待时间。保留原游戏自身的耳机/提示界面及后台诊断日志。保留原生玩家 HUD 就绪计时日志，方便排查；没有强制 60 秒隐藏或虚假加载完成。

旧 Makefile 不会因为 APP_VERSION 参数改变而自动重编译旧入口对象，因此日志可能显示旧版本字符串，即使软件包元数据已经更新。加入版本/入口配置指纹依赖，版本改变时重建对象及 NACP。本次实际 ELF 已检查含 `0.4.8-NoBar`，打包元数据版本为 0.4.8。旧日志的 0.4.6 标签不能单独证明未安装 0.4.7。

## 保持的配置

L 按住跑步，ZL 瞄准；L3 陀螺开关、方向键下零重力跳跃、R3 寻路及其余 0.4.7 键位不变。保留中文、现有显示配置、53 张匹配高清子集与原图回退。原有基于真实读取进展的有限加载预算覆盖所有关卡/检查点恢复调用，不因取消进度条而删除。
