# 交付要求（2026-10-20 用户确认）

## 应用名称与图标

- 显示名称：**Dead Space Mobile**。
- 使用用户2026-10-20提供的方形图标；构建资源为 `switch/assets/icon.jpg`。
- 最终 NSP 的主菜单名称和图标使用同一配置。

## 下一版本的开发路径

- 应用标识和 SD 卡开发目录统一使用 `deadspacemobile`。
- 开发数据路径：`sdmc:/switch/deadspacemobile/gamedata/`。
- 开发诊断日志：`sdmc:/switch/deadspacemobile/diagnostics.log`。
- 数据导入工具、程序常量、测试包目录和安装说明必须同批更新，避免与另一款使用 `deadspace` 目录的游戏冲突。
- 已发出的 0.2.0 二进制仍读取旧目录；上述路径变更将在下一版二进制中交付。

## 最终交付形式

最终目标是可直接安装运行的完整 NSP 整合包。游戏执行程序、匹配的原版库和运行所需资源均随安装包内置；用户安装后无需手动准备外部游戏数据文件夹，也不依赖 SD 卡上的额外 NRO 启动目标。

实现上，游戏库与只读资源从包内 RomFS 读取；存档和设置由程序管理可写存储。开发阶段的外置数据路径用于调试，最终安装运行不能依赖该路径。开发标识、内部存储标识和后续包元数据统一以 `deadspacemobile` 为基础。

## 最终验收

1. 在没有预先复制游戏数据目录的测试环境安装 NSP，并能直接进入游戏。
2. 由包内资源完成实际第一关移动、瞄准、射击、画面和声音。
3. 菜单、触摸、手柄及切关可用，存档在退出重启后可正常读取。
4. 在整个验收过程中不读取另一款游戏的 `deadspace` 目录。

当前 0.3.0 是含构造函数运行时和内置资源验证的开发原型；游戏生命周期和平台接口仍待接通。本文件记录用户指定的后续交付要求，不代表已经完成可玩 NSP。
