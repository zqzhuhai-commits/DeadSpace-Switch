## 上游更新审查

该提交新增第二帧、资源调用和状态写入追踪，也加入同步执行 `pthread_create` 的实验路径。同步调用会让父线程无法继续发布后台线程正在等待的状态，因此又修改了预加载标志、休眠时的对象字段，以及后续帧的任务标志。这些写入只能作为探索线索，不能证明正常线程语义或资源加载已经完成。

本次用协作上下文调度替换上述同步调用，删除这些游戏地址写入。诊断也不再读取溢出 32 位的硬编码地址、空场景指针，或为每次读写扩充调试直方图。旧实验完整保留在 Git 历史中。保留资源调用描述接口；运行器现在提供实际 guest LR，避免诊断改变 guest 状态。`isContentReady` 恢复检查实际配置文件。

## 实现

- 一台 Dynarmic ARM32 CPU，按导入调用边界和最多 100,000 指令的时间片切换上下文；不在 Dynarmic 回调内部重入运行器。
- 保存 r0–r15、全部 VFP 扩展寄存器、CPSR/FPSCR；切换时清除独占访问状态。
- 主线程保留 2 MiB 栈；最多 32 个独立工作栈，单栈 16 KiB–2 MiB，位于 `0x21000000..0x25000000`。退出并回收后可复用，重新使用前清除旧栈页。线程 ID 单调分配并设总量上限。
- `pthread_create` 排队后立即返回父线程，工作线程随后获得执行权；正常返回和 `pthread_exit` 都进入退出流程。`join` 等待、写回结果并回收；分离线程退出后回收。
- mutex 的所有权、递归计数、等待及移交；信号量等待与唤醒。JNI monitor 具有递归、所有权、空对象和非法退出检查，争用时等待。
- 各线程具有独立 TLS、errno 地址和 Java 待处理异常。线程结束时执行最多四轮 TLS 析构回调。
- 休眠及 `clock_gettime` 使用运行器虚拟时间；全部任务休眠时推进到最早期限。没有可执行任务且不存在可到期休眠时报告死锁。
- setjmp/longjmp 使用 guest 不透明令牌保存各线程的核心/VFP 状态，`longjmp(..., 0)` 返回 1；拒绝跨线程、跨嵌套 host 回调的跳转。未把宿主 libc 的缓冲布局写入 guest 内存。
- GL 帧缓冲/渲染缓冲绑定查询按单个整数处理；回读测试检查写入边界。已返回的 DrawFrame 单独累计，阻塞时也可定位真实进度。
- 仅明确列举的浮点数学函数去掉 `f` 后缀，避免误改其他导入名。

## 验证

已在本次环境完成：

1. 主机 Release 全部目标构建。
2. `ds-thread-arm-test`：执行合成 ARM32 指令。后台线程先等待，父线程以真实 ARM store 发布标志并等待 join；后台线程恢复、写入 42、退出，父线程收到 42。发生三次上下文切换、一次休眠；ARM 栈和浮点状态保留。测试没有写入任何游戏私有完成标志。
3. `ds-thread-test`：上下文/TLS/异常隔离、轮转、等待/唤醒、休眠期限、join 结果、分离退出、栈复用、死锁和不透明跳转边界。
4. ASan/UBSan 回归：JNI、内存、线程、KTX/压缩纹理解码和 native Mesa GL 回读。LeakSanitizer 在此环境禁用。
5. `hd_romfs_test.py`：只保留 donor 精确匹配的 KTX；内嵌清单描述实际文件数、大小和原包来源；保留事务回滚及原始库白名单。
6. 生命周期/JNI/GL 使用 `-Wall -Wextra -Werror -fsyntax-only` 检查。
