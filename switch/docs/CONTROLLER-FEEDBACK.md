## 按键目标与实现

根据用户附图，后续明确将武器旋转从 R3 改为 L3。Switch 使用 libnx PadState
读取物理按键和摇杆，不依赖 SDL 控制器数据库对任天堂 ABXY 的命名。
SDL 的重复控制器事件被忽略，桌面 SDL 输入仍可测试。

| Switch | 游戏路径 |
| --- | --- |
| 左摇杆 | 前触屏持续移动手势，归中释放 |
| 右摇杆 | 后触板模块 1100，每帧重新开始镜头拖动 |
| ZL / ZR | Android 102 / 103，瞄准 / 射击 |
| L | Android 100，瞄准时静态力场；原游戏该键未瞄准时会快速转身 |
| R | Android 99，换弹 |
| A / B | Android 23 / 4，互动 / 念力；菜单 A 点击光标 |
| X | Android 20，原 donor 十字键下动作，目标为等离子锯攻击 |
| Y | Android 100，快速转身；原游戏瞄准时会静态力场 |
| 十字键左 / 右 | Android 21 / 22，上一把 / 下一把武器 |
| 十字键上 | Android 19，目标为定位器 |
| 十字键下 | 复现原移动版零重力跳跃加速度序列 |
| + / − | Android 108 / 109，菜单 / HUD |
| **L3** | 复现武器倾斜加速度序列，目标为切割枪横竖切换 |
| R3 | 切换菜单光标；菜单十字键移动光标 |

按键语义参考 [Vita 端控制说明](https://github.com/v-atamanenko/deadspace-vita#controls)
和该项目 `loader/reimpl/controls.c` 的 Android 键值。上下方向动作的具体对应仍需
真实 donor/实机确认，不能把发送 Android 键值的测试当作游戏动作已验收。
L 与 Y 保留原游戏的上下文行为，未打补丁将其强制拆成两个游戏动作。
同一个游戏键有多个物理来源时，仅在最后一个来源释放后发送 key-up。

## 运动传感器

从掌机、Pro 手柄或双 Joy-Con 的六轴设备读取加速度，以 SI 单位通过原始
`AccelerometerAndroidDelegate.NativeOnAcceleration` 的 ARM32 softfp ABI 转发。
L3 和十字键下是无传感器控制器也可使用的替代手势，非阻塞并按时间间隔发送；
物理样本不会在替代序列中间覆盖它。手势样本沿用项目已有的 MIT 来源。

这接通的是原游戏的倾斜/晃动输入；没有添加“陀螺仪转动瞄准”。传感器朝向、
触发阈值和低帧率下的动作识别仍需要实机验证。

## 中文、性能和退出

`--chinese-apk` 打包时，在原有 schema 和字体头验证通过后，也将中文数据库
写入 en-us 回退路径，并将 staging 数据中现有 TTF 字体文件名对应到 Unicode 字体。
这使仍选中英文的存档/旧 donor 也能读取中文文本，不改写或删除存档。
其他语言的显式选择不被覆盖。仍需验证字形、换行和字符串 ID 的实际显示。

原来的每次 pointer guest_call 都记录 BEGIN/END，持续双摇杆可每帧触发多次
SD 文件打开/刷新/关闭。候选移除指针和加速度调用的这类逐次检查点；保留有界
内存 trace、启动、按键和周期汇总日志。没有实机 FPS 或十分钟加载的计时结果。

明确支持 `MainActivity.finish()V`：请求退出后先让当前 guest 调用返回，在帧边界
停止，不在 guest 栈仍执行时销毁 SDL/GL。成功请求退出时独立应用清理 RomFS 和
控制台后返回 0；失败仍显示诊断。它针对已确认缺失的 Java 退出方法，不能证明
所有实机退出错误具有相同原因。
