# 0.4.1-startup 启动诊断版

当前收到的 diagnostics (1).log 首条 BOOT 标记为 0.3.8，且完成至少 2,013 帧，包含高清纹理命中。它与本次 0.4.0 独立 NSP 的版本、默认材质设置和日志格式不一致，不能解释用户报告的“点击后立即报错”。文件复制时间不能证明内容来自最新启动。

请安装 `DeadSpace-Mobile-ZH-0.4.1-Startup.nsp`，确认该次启动的软件版本为 **0.4.1-startup**。程序与资源仍全部内置，Title ID 与 0.4.0 相同。已有 SD 存档不覆盖。

这是定位故障的诊断候选版，尚未确认故障根因，也未在 Switch 实机或模拟器上运行。不能将重新封装及校验通过当成已修复启动。

## 本版记录

- libnx 服务与 SD 初始化后、全局 C++ 构造函数前，重写 `/switch/deadspacemobile/startup-latest.log`，首条含确切版本。
- 记录程序入口、实际系统版本编码、控制台、RomFS 挂载结果、数据检查、SDL、GLES1、音频、原始 ELF、JIT 和游戏构造函数阶段。
- 游戏初始化抛出的可捕获异常写入日志，保留“按 + 退出”提示。系统加载前失败、libnx 服务初始化失败或原生 CPU 异常仍可能无法记录。
- 修正此前仅创建末级目录的问题：先创建 `/switch/`，再创建程序日志目录。没有 SD 写权限或介质故障时依然无法生成文件。

## 测试后需要的信息

1. 若生成 `startup-latest.log`，复制到电脑并提供完整路径。首条应含 `version=0.4.1-startup`，该文件每次启动重写，不需混用旧 diagnostics.log。
2. 若没有该文件，提供系统弹窗的完整文字或错误码；这有助于区分程序入口前失败、服务初始化失败和 SD 写入失败。
3. 一并记录 Switch 系统版本、Atmosphère 版本、是否成功安装以及报错发生时是否出现任何程序画面。

所有构建和封装校验均在电脑完成，安装、实机启动和性能仍待验收。密钥只从原位置读取，不加入安装包或公开仓库。
