## 旧架构与重新制作路线

审查仓库基线 `48fcea2663a7b87e5ad387015ab910953b6275c2`。Linux 上游通过 ARM32 ELF 加载器、Bionic/JNI 兼容层、SDL/GL 运行原库；Switch 目录通过 AArch64/libnx、Dynarmic A32、guest JNI/线程及 GLES 桥接原型推进。默认 Makefile 生成诊断 NRO，CPU_PROBE 是可选运行时；未发现完整 NSP 构建目标。

旧版协作线程文档还列出文件指针截断、文件描述符和 mmap 生命周期等待修项；原生 GL 子集、矩阵调色板、游戏音频、输入、持久化和持续游戏循环仍需验证。上述是源码及项目记录，不是本次复现的卡顿原因。

原始 C/C++ 游戏引擎源码不在所给材料中，无法仅凭 ARM32 .so 直接重编译成 AArch64 原生引擎。新运行时应独立建立最小垂直切片：固定 donor -> 映像/线程与文件语义 -> 实际 GL -> 第一关 -> 音频/输入/存档。Dynarmic、开放图形解码器等可评估复用，但每项都须重新验证。只有取得可移植引擎源码及许可，才另评估真正原生重编译路线。

先使用原始分辨率资源，关闭可选高清替换，记录实际内部渲染分辨率。不能把高清解码或调试追踪开销带入默认运行路径。减少跨 ABI 的逐调用分配、同步和拷贝须以测量为依据；不跳过绘制、伪造成功标志或修改关卡逻辑来制造帧率。

## 性能门槛（目标，尚未测量）

默认以稳定 30 FPS 为首个目标，不承诺 60 FPS。用第一关固定路线，分别测试掌机和底座正常频率；记录机型、系统、构建提交、资源哈希、分辨率和温度条件。10 分钟预热后采集至少 10 分钟：呈现帧间隔 p50/p95/p99、超过 50/100 ms 的卡顿数、CPU guest/桥接/渲染耗时、GPU 时间、纹理解码/上传峰值、内存和音频欠载。CPU/GPU 耗时可能重叠，不能简单相加。

初始门槛：稳态 p95 呈现间隔不高于 36.7 ms，p99 不高于 50 ms；明确标注加载/切关停顿，并另外报告包含它们的全流程统计。不以菜单 FPS、单三角形或诊断程序启动成功代表游戏性能。对照旧版必须使用相同设备、场景和采样方式。

## 按键方案（待接入、待确认原游戏事件）

| Switch 输入 | 目标行为 |
|---|---|
| 左摇杆 | 移动，径向死区初值 0.15、可调 |
| 右摇杆 | 视角/瞄准，可调灵敏度和反转 Y |
| ZL / ZR | 瞄准 / 射击 |
| A / B | 菜单确认、交互 / 返回 |
| X / Y | 换弹 / 治疗，须核对游戏动作 |
| L / R | 武器模式切换 / 踩踏或近战，须核对游戏动作 |
| 十字键 | 武器选择；菜单中移动指针 |
| 左摇杆按下 | 冲刺，须核对游戏动作 |
| 右摇杆按下 | 显示/隐藏菜单指针 |
| + / - | 暂停 / 目标或地图 |
| 触摸 | 菜单直接点击，坐标按视口换算 |

Zero-G 跳跃等特殊动作必须在相关关卡补齐并提供重映射。按下与释放成对发送；焦点丢失/断连释放全部输入；菜单与游戏上下文分离；避免同一按键同时触发确认和射击。这是设计表，不是已工作的控制实现。
